① 从 Möbius 变换到 Kleinian 极限集

推文的动画分三幕:(1) Möbius 变换把圆和直线送到圆和直线;(2) 四个生成元 A, B, A⁻¹, B⁻¹ 把一个圆变成 4 个、再变成 12 个……越来越小的圆(1 → 4 → 12);(3) 轨道的累积点组成一条错综复杂的极限集。本页把每一幕拆成可以动手的一步,最后再给出一种完全不同的“反向折叠”算法做对比。

页面里所有 黑底彩色 的图都是实时运行的 WebGPU 着色器(compute 或 fragment);灰色线条的几何示意图用 Canvas2D 绘制。

步骤 1 · Möbius 变换:圆 → 圆,直线 → 圆

一个 Möbius 变换是 T(z) = (az + b)/(cz + d),系数是复数,且 ad − bc = 1(归一化)。它由三类基本操作复合而成:

z₁ = c·z + d          旋转 + 缩放 + 平移
z₂ = 1 / z₁           “反演”(单位圆内外互换,再关于实轴翻转)
z₃ = a/c − z₂ / c     再一次 旋转 + 缩放 + 平移

前后两步只会把圆变圆;1/z 也会把圆(或直线)变成圆(或直线)——所以整个 T 保圆。矩阵乘法 = 变换复合:T_M ∘ T_N = T_{MN},逆变换是 [[d, −b], [−c, a]]。这让我们能用矩阵代数来管理“几百万个变换的复合”。

步骤 2 · 生成元与“1 → 4 → 12”的圆树

取两个 Möbius 变换 A, B 及其逆 A⁻¹, B⁻¹,共 4 个生成元。这些变换生成一个群:所有由它们组成的“单词” w = x₁x₂…xₙ(xᵢ ∈ {A,B,A⁻¹,B⁻¹})。约去 x·x⁻¹ 后,长度为 n 的约化单词有 4·3ⁿ⁻¹ 个:1 → 4 → 12 → 36 → 108 …

下面选定一个群(Indra's Pearls 里的 Grandma 配方:只需给定 tr A, tr B,约束 tr[A,B] = −2,tr AB 由 tr²A + tr²B + tr²AB = trA·trB·trAB 解出,见 src/math.js 的 grandma())。原始配方把换位子的不动点(尖点)放在 ∞,极限集是一条无限延伸的周期带;这里再做一次共轭 z ↦ 1/(z − z₀)(conjugateInv(),z₀ = −i),把尖点搬到原点附近 —— 极限集就成了视频里那条闭合、顶部带尖点缺口的“龙”。黄色圆是一个起始圆(可以拖动);每次把它变成 4 个、12 个、36 个…像,颜色表示单词的第一个字母(A 青 / B 紫 / A⁻¹ 蓝 / B⁻¹ 粉),细线连着“父圆”和“子圆”的圆心,就像视频里那样。

观察:每多一层,圆就小一圈,而且它们都收向同一条看不见的曲线——极限集。这些圆之所以互不重叠、层层嵌套,是因为 A, B 把某个区域(“基本域”)的外部压进了小圆盘里。

步骤 3 · 迭代一个点:随机走一条词

圆树太“大”了:每层要算 3ⁿ 个像。更省的办法是只跟踪一个点:每一步随机挑一个生成元(但不能立刻抵消上一步),作用到当前点上。点击图中任意位置选起点,再“走 N 步”。几十步之后点就掉进了极限集附近,并在它上面“游荡”。

步骤 4 · 混沌游戏:100 万个点累积成极限集(推文的做法)

把步骤 3 并行化:GPU 上同时跑成千上万个粒子,每个粒子各自随机套用生成元;落到屏幕哪个像素,就在那个像素的计数器上 atomicAdd(1),最后把计数用 log 色调映射。粒子先“预热”12 步(丢掉还没靠近极限集的点)。代码见 src/chaos.js —— 一个 compute shader + 一个 fragment shader。

(可以在任意一张图上拖动/滚轮缩放,四张同步。)点越多,极限集的细节越清晰;靠近抛物不动点(尖点)的地方点特别稀疏——这是随机游戏的固有缺点:到达尖点附近的概率很低。

步骤 5 · 换个角度:逐像素“反向折叠”

另一种算法不画轨道,而是对屏幕上每个像素 z问:“用群里的元素把 z 拉回基本域,要几步?” 极限集上的点永远拉不回去,所以步数越大的像素离极限集越近。

对 Schottky 群,基本域就是“所有圆之外”。每个生成元由一对圆 (a, A) 给出:

g(z)   = cA + ρ / (z − ca),  ρ = ra·rA·e^{iθ}    把 圆a 的外部 映到 圆A 的内部
g⁻¹(w) = ca + ρ / (w − cA)                        把 圆A 的外部 映到 圆a 的内部

规则:点落在圆 a 里 → 施加 g(把它推到圆 A 之外);
      点落在圆 A 里 → 施加 g⁻¹(推到圆 a 之外);
      落在所有圆之外 → 停止,记下步数。

下面 6 张图是同一个群,最多允许 N 步:白色 = 已经在基本域里(0 步);彩色 = 用了 1…N 步后被拉进基本域(颜色 = 最后一步用的生成元);深灰 = N 步还没拉进去。N 增大,深灰区域收缩成极限集。

最后一张是完整渲染(按生成元着色,40 步)。把鼠标移到图上,白线就是该点被折叠的路径:每一步都跳进另一个圆里,一路缩小,最后落进基本域。

步骤 6 · 带抛物元的情形(Maskit 切片):两种算法对照

Grandma 的龙形极限集通常带抛物元(尖点)。取 T(z) = z + 2、S(z) = 1/z + c(c = −b + ia)。这个群还有一个隐藏的对称:椭圆元 R(z) = c − z(旋转 180°)。于是逐像素算法变成:

每轮:  把 z 平移回宽度 2 的带内 (T)
       如果 z 在中线之上:z ← c − z   (R)
       z ← 1/z + c                     (S)
       如果 z 掉到带 0 < Im z < a 之外:停止,记下步数

左:混沌游戏(正向);右:逐像素折叠(反向),两者描绘的是同一条极限集。注意带尖点时反向折叠没有“稀疏”问题。

小结:两条路线

正向迭代(推文)

轨道点 → 累积直方图。任何由矩阵给出的群都能画(Grandma / Jørgensen / 一般 Möbius)。缺点:尖点附近采样稀疏,需要大量点。代码:chaos.js

反向折叠

逐像素把点拉回基本域。每个像素独立、没有噪声,可任意放大;但要先知道基本域(Schottky 圆、Maskit 带 + 对合)。代码:shaders.js
